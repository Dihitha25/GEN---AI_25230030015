# Week 6 Generative AI Programming Practical

## Llama 3.2 Golden Set Baseline Evaluation

This project runs a fixed set of questions against a local Llama 3.2 model using Ollama. It compares each model response with a supplied expected answer, checks how many expected keywords appear in the response, and writes a CSV baseline report.

The baseline is labeled **Release v0.1**. Its purpose is to record an initial, repeatable result before changing the model, prompt, or evaluation approach. The keyword score is a simple coverage measure; it does not prove that an answer is correct or complete.

## Learning objectives

This practical gives you a chance to:

- Call a locally running LLM from a Python program.
- Store a fixed set of questions, expected answers, keywords, and sources in JSON.
- Run the same questions against one model to establish a baseline.
- Compare generated answers with expected answers using keyword coverage.
- Save results, model name, and release label to a CSV file.
- Review failures and recognize the limits of a basic automated score.

## Project files

| File | Purpose |
| --- | --- |
| `main.py` | Loads the question set, sends questions to Ollama, scores responses, prints a summary, and writes the CSV report. |
| `golden_set.json` | Contains 30 question records. Each record has an ID, question, expected answer, keywords, and source. |
| `requirements.txt` | Lists the Python package required to send HTTP requests to Ollama. |
| `.gitignore` | Excludes Python cache files from Git. |
| `baseline_results.csv` | Generated by the program after it runs. Contains one result row per question. |

## Requirements

- Windows, macOS, or Linux.
- Python installed and available through the lab virtual environment.
- Ollama installed and running on the computer.
- The `llama3.2` model downloaded through Ollama.
- Enough free disk space and memory to run the selected local model.

The Week 6 guide uses Ollama version 0.40.13 as its example. A later compatible version may also work. Model startup and response time depend on the computer's hardware.

## Install and start Ollama

Install Ollama using its official installer for your operating system. On Windows, complete the installer and then open a new PowerShell terminal so the `ollama` command is available.

Check that Ollama is available:

```powershell
ollama --version
```

Download the model used by this project:

```powershell
ollama pull llama3.2
```

Ollama normally runs a local service at `http://localhost:11434`. If the model pull succeeds but the Python program cannot connect, start or reopen the Ollama application and try again.

You can confirm the model is installed with:

```powershell
ollama list
```

The output should include `llama3.2`.

## Run the baseline

Make sure Ollama is running and `llama3.2` is installed. From the `LAB\week 6` folder, run:

```powershell
python main.py
```

The program reads `golden_set.json`, then sends each question to the local Ollama generate endpoint. It uses a temperature of `0` to reduce variation between runs. Each request has a 120-second timeout.

For every question, the terminal shows the question, generated response, expected answer, matched and missing keywords, percentage score, and status. At the end, the program prints a summary and saves the full result set to `baseline_results.csv` in the same folder as `main.py`.

## How the evaluation works

Each question in `golden_set.json` includes:

- `id` — a stable identifier such as `Q001`.
- `question` — the prompt sent to the model.
- `expected_answer` — a reference answer for review.
- `keywords` — terms used for the automatic coverage score.
- `source` — a reference link for the expected information.

The program searches the model response for each keyword without regard to capitalization. The score is:

```text
matched keyword count / total expected keyword count * 100
```

A score of **60% or higher** is labeled `PASS`. A lower score is labeled `REVIEW`. A request or evaluation error is labeled `ERROR` and receives a score of zero.

The score is intentionally simple. It can miss correct answers that use different wording, and it can give credit to a response that contains keywords but explains them incorrectly. Read the generated answers and check the cited sources before drawing conclusions about model quality.

## CSV report fields

The generated `baseline_results.csv` contains these columns:

| Column | Description |
| --- | --- |
| `Question_ID` | Golden set ID for the question. |
| `Question` | Text sent to the model. |
| `Expected_Answer` | Reference answer supplied with the question. |
| `LLM_Answer` | Text returned by Ollama, or blank if the request failed. |
| `Matched_Keywords` | Expected keywords found in the response. |
| `Missing_Keywords` | Expected keywords not found in the response. |
| `Score` | Keyword coverage percentage from 0 to 100. |
| `Status` | `PASS`, `REVIEW`, or `ERROR`. |
| `Source` | Reference URL from the golden set. |
| `Model` | Model name used for the run (`llama3.2`). |
| `Release` | Baseline label (`v0.1`). |

The CSV is written as UTF-8 with a byte-order mark so spreadsheet applications can display multilingual text more reliably. Each run replaces the previous `baseline_results.csv`; copy or rename a report before another run if you need to preserve it.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `ModuleNotFoundError: No module named 'requests'` | Activate the lab environment and run `python -m pip install -r requirements.txt`. |
| `ollama` is not recognized | Install Ollama, then open a new terminal. Check that its install directory is available on `PATH`. |
| Connection refused at `localhost:11434` | Start or reopen Ollama and retry. The Python program expects the local Ollama service at this address. |
| Model not found | Run `ollama pull llama3.2`, then check the installation with `ollama list`. |
| Request timeout | The model may still be loading or the computer may be slow. Confirm Ollama is responsive and retry. |
| A row has status `ERROR` | Read the request error printed for that question. If Ollama was stopped during the run, start it and run the evaluation again. |
| Many answers are marked `REVIEW` | Inspect the answer text. The keyword list may be too strict or the model may have used valid alternate wording. Review the golden set and source before changing scoring rules. |
| CSV text looks garbled | Open the UTF-8 CSV with a spreadsheet application that detects UTF-8, or import it and select UTF-8 encoding. |

## Changing the question set

You can add, edit, or remove question records in `golden_set.json`. Keep the file valid JSON and ensure every question has all five required fields: `id`, `question`, `expected_answer`, `keywords`, and `source`.

Keep IDs unique so you can identify questions in the CSV. Choose keywords that are meaningful indicators of the expected answer, not merely common words. After changing the question set, rerun:

```powershell
python main.py
```

Changing the questions, model, or scoring method changes the evaluation setup. Record those changes when comparing a later run with the v0.1 baseline.
